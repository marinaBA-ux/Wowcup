# Бесплатная проверка билетов через GitHub Actions

Workflow запускает проверку примерно каждые 10 минут и пишет в Telegram при первом обнаружении признаков доступной покупки.

## Важные ограничения
- GitHub Actions по расписанию может запускаться с задержкой; точность «ровно каждые 10 минут» не гарантируется.
- Для публичных репозиториев стандартные GitHub-hosted runners бесплатны. В приватном репозитории действует месячная квота GitHub Free; частые запуски могут её превысить.
- Код репозитория будет публичным, если сделать репозиторий public. Токен бота, chat ID и URL хранятся в GitHub Secrets и в код не попадают.
- Проверка ориентируется на текстовые признаки виджета. После первого запуска обязательно проверь логи и реальное распознавание.
- Бот не гарантирует обнаружение билетов, если Яндекс меняет интерфейс, блокирует автоматические запросы или отдаёт страницу без текста о покупке.

## Установка
1. Загрузи `monitor.py`, `requirements-actions.txt` и `.github/workflows/check.yml` в корень своего репозитория (сохрани структуру папок).
2. В Telegram открой своего бота, нажми Start или отправь `/start`.
3. Получи chat ID:
   - В браузере открой `https://api.telegram.org/bot<ТОКЕН>/getUpdates`, подставив токен локально в адресную строку.
   - Найди `message` → `chat` → `id`.
   - Не делись этой ссылкой и не публикуй токен. После получения chat ID удали сообщение `/start` или вызови getUpdates ещё раз, если нужно.
4. В GitHub открой репозиторий → Settings → Secrets and variables → Actions → New repository secret.
5. Создай три secrets:
   - `TELEGRAM_BOT_TOKEN` — токен BotFather.
   - `TELEGRAM_CHAT_ID` — числовой chat ID из getUpdates.
   - `TARGET_URL` — ссылка на нужную сессию Яндекс Афиши.
6. Вкладка Actions → выбери `Check Afisha tickets` → Run workflow для теста.
7. Открой Logs и проверь, что job завершился успешно. В дальнейшем workflow будет запускаться по расписанию.

## Если workflow не запускается
- Убедись, что Actions включены в Settings → Actions → General.
- Проверь, что файл лежит точно по пути `.github/workflows/check.yml`.
- Scheduled workflows работают на default branch репозитория.
- GitHub может задерживать scheduled runs, особенно при высокой нагрузке.

## Состояние уведомлений
Workflow использует GitHub Actions cache для переноса статуса между запусками, чтобы не слать одинаковое уведомление при каждом цикле. Если cache будет очищен или истечёт, уведомление может повториться.
